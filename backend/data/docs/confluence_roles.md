# Confluence roles and permissions

Source: https://support.atlassian.com/confluence-cloud/docs/what-are-confluences-roles/
Additional source: https://support.atlassian.com/confluence-cloud/docs/manage-user-roles/

This is a concise reference for AccessPilot recommendations. Confluence access is managed at the site and space level. The exact permissions can vary by plan and custom roles.

## Viewer

Use when someone only needs to read pages in an assigned space.

Typical request language: read documentation, browse a knowledge space, view onboarding pages.

## Collaborator

Use when someone needs to create and edit pages or contribute to team documentation.

Typical request language: write documentation, edit pages, update onboarding content, add comments.

## Manager

Use when someone needs to manage space content and space settings beyond ordinary page editing.

Typical request language: manage a space, organize content, manage space settings, maintain a team knowledge area.

## Admin

Use only for space owners or IT administrators who manage access and the full configuration of a space. This is a privileged role.

Typical request language: manage permissions, assign space roles, configure the space, manage restrictions.

## Least-privilege guidance

- Read pages: Viewer.
- Create or edit pages: Collaborator.
- Manage content and space settings: Manager.
- Manage access or full space configuration: Admin.

## Important context

Confluence role-based access can include default and custom roles. Space permissions and content restrictions may further limit what a role can do. The application owner should confirm the final access level.
